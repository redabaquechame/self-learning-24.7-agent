# SC-2C safe practice and teaching-canvas review

**Scope:** closed explanatory scenes, deterministic graph validation,
interactive slider/reset/Stop state, disposable practice copies, reveal-aware
variants, artifact verification, native WPF rendering and isolated practice
ink.  
**Review dimensions:** security, correctness, performance, maintainability.  
**Current verdict:** locally verified and reviewed with native synthetic render
evidence; qualified-pack integration and human native application evidence
remain open.

## Resolved findings

1. **Scene output could carry executable content.** Exact schemas accept only
   seven primitive kinds and three expression node kinds. Unknown fields,
   scripts and unapproved operations refuse in Python and native code.
2. **A convincing graph could contradict its equation.** Python and native
   validators recompute every sample with bounded deterministic arithmetic and
   reject mismatches before render.
3. **Python and native scene formats could drift.** Both consume the checked
   `tests/fixtures/tutor_canvas_render_v1.json` generated by the Python render
   contract.
4. **A slider could change its label without changing the concept.** Slider
   values update the root state, the slider payload and every dependent graph
   sample.
5. **A practice request could open a production document.** Only synthetic or
   explicitly licensed practice records pass. `PRODUCTION_DOCUMENT` refuses
   before a destination is created.
6. **Reset could be redirected to a real project path.** The destination is
   derived from validated project/user/practice identifiers and rechecked on
   every operation.
7. **Expected results or watched files could change unnoticed.** Expected JSON
   is digest-bound; source and watch digests are checked before verification or
   reset.
8. **A filename change could be called transfer.** Identical content and task
   signatures remain ineligible even when the artifact name changes.
9. **Help could disappear from learner evidence.** Worked, partial and
   independent modes enforce answer, hint and no-help accounting respectively;
   exposed independent variants refuse.
10. **Drawing could modify the source application.** Native ink owns only
    in-memory points and a source digest string. It holds no document handle,
    file path or application-input capability; Reset and Stop clear the ink.
11. **Malformed render data could leave a stale concept visible.** A new native
    load clears the prior scene before parsing; invalid input leaves the canvas
    blank.
12. **Subjective work could receive a mechanical pass.** The subjective
    verifier returns review-required and never a mechanical success.

## Security assessment

- Practice writes use File Authority and land only below the generated
  `artifacts/tutor-practice/` path. No execution or application-input function
  is reachable from either new Python module.
- Source size, expected-result size, watched paths, primitives, expression
  depth, graph samples, slider state and native ink are bounded.
- JSON rejects duplicate keys in the practice artifact and duplicate or
  unknown fields in native render data.
- The returned session record is a mechanism contract, not an authorization
  token. The host must retain the authoritative record outside model-visible
  content and bind it to the qualified pack assignment.

## Correctness assessment

- T041 rejects executable expression nodes and active primitive fields.
- T042 declines a production document and creates a byte-exact copy from a
  digest-bound synthetic source through File Authority.
- T043 rejects a graph/equation mismatch in Python and native code.
- T044 rejects filename-only novelty and requires independent, unexposed,
  declared task variation before transfer eligibility.
- T045 has offline source-digest evidence and a native synthetic WPF witness:
  the control rendered 11,819 non-white pixels, held an ink stroke only in
  memory, reset it, preserved the bound source digest and cleared it on Stop.
- The native project builds with zero warnings and zero errors under the pinned
  .NET SDK and retains the real test-owned capture witness.

## Performance assessment

- Scenes allow at most 64 primitives, 64 graph samples, 64 expression nodes,
  depth eight and 16 slider variables. Native payloads are capped at one MiB.
- Practice sources are capped at eight MiB, expected JSON at 256 KiB and watch
  sets at 64 paths. No provider, process or network call occurs.

## Maintainability assessment

- `tutor_canvas.py` owns validation, deterministic evaluation and render-state
  generation. `TeachingCanvas.cs` owns native drawing and local ink.
- `tutor_practice.py` owns safe-copy, verification, reset/Stop and variant
  semantics. It reuses `fileauth.py` rather than adding a file path.
- Python and native tests are registered in the suite, doctor, evidence map,
  package checks and mutation harness.

## Evidence boundary

SC-2C is not accepted as a complete packet. SC-2A and SC-2B are not fully
qualified dependencies. The caller-supplied practice source/expected result is
not yet joined to a real qualified pack assignment, and the native canvas is
not wired to the authenticated companion request flow. T045 does not include a
human drawing over a supported real application while an independent observer
checks the document bytes. No content qualification, human learning,
retention, accessibility, deployment, release or market-superiority claim
follows.
