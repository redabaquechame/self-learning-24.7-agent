# Genuine native journey: current integration gaps

Recorded 2026-10-13 during the live, frozen native-continuity regression. This is source-backed integration preparation, not implementation, an accepted packet, or a substitute for the original whole-platform scope. Product source remains frozen until campaign session38570 is terminal.

## Binding requirements

Original `../planning/screen-tutor-v2-2026-09-14/execution/WORK_PACKAGES.md`, SC-1A and SC-2D: actual selected-source capture and native transport; installed novice summon → select → useful answer → highlight → Stop; distinct close/cancel semantics; keyboard/screen-reader paths; recorded human friction. ADR002 requires a per-user native-owned pipe, a new launch secret, mutual versioned handshake, typed bounded messages, sequence/correlation/deadline/cancellation, and opaque single-use shared-memory frame transfer. The pipe creates no grant. ADR007/010 retain qualified model accounting and current source/geometry overlay binding.

## Current source findings

1. `App.xaml` uses `StartupUri=SessionWindow.xaml`; `App.xaml.cs` supplies no host launch/bootstrap. `SessionWindow` creates its own capture/session, registers only its shortcut at SourceInitialized, and never constructs OwnerBridge. No actual authenticated host is connected by this window.
2. `SessionWindow.xaml` AskButton is permanently disabled and has no Click handler. Current selection shows a truthful authorization-pending status. `StartAuthorizedCapture` exists in CaptureSession but is not invoked by the visible window. Removing the disabled flag alone would not implement the journey.
3. `OwnerBridge` supplies current-user-only native pipe acceptance and authenticated inbound reading, including duplicate/replay/refusal checks. It has no authenticated outbound operation or mutual handshake orchestration. Its existing MAC material signs session/epoch/sequence/body but not deadline; the next transport implementation must integrity-bind every policy-bearing envelope field and prove deadline alteration refused. This is a source concern pending a targeted runtime witness, not an already reproduced new defect.
4. `TutorSession.select_source` advances the host capture epoch independently. Native CaptureSession advances its epoch on selection, invalidation and Stop. Integration must admit the exact native selection receipt and bind both sides consistently; silently dropping an epoch mismatch would break the existing stale-source boundary. Ready-source replacement also needs an explicit host lifecycle, not direct mutation of host source fields.
5. Native captures are BGRA8 and bounded to 32 MiB/frame; qualified image dispatch accepts bounded PNG/JPEG in a one-shot process-local store. There is no real native → opaque shared memory → host image-store conversion in the visible flow. Keep pixel data out of JSON/logs/durable records. Stop/source loss/transport loss must revoke and wipe both transport and host transient buffers.
6. `TutorService.ask` admits a selected-source request and returns the instruction-validation verdict. It does not return the actual instruction content for presentation, and its owner_state argument is a snapshot. A real host adapter needs current host policy before dispatch and release, a source-bound validated answer payload, cancellation/idempotency, and a preserved read-only authority boundary. Existing `investigate` already uses a live policy reader; reuse that pattern rather than weakening admission.
7. `tutor_gateway.ask_image` returns a source-bound qualified image-result record with usage/cost accounting; this is not itself a complete tutor instruction or qualified target. Preserve its one-shot image, reservation, exact provider capability and stale/cancel suppression. No approved provider campaign has run. A controlled process test can prove plumbing, not real-model helpfulness or content quality.
8. `StructuralObservationWorker` runs an injected bounded observer off the UI dispatcher; no actual source-scoped UI Automation provider is connected by SessionWindow. `OverlayRenderer` validates/schedules/releases inert primitives but creates no visible overlay window. Actual target/geometry acquisition, drawing and current-binding invalidation are missing.
9. `CaptureSession.PrepareSelectedItemLocked` derives its NativeHandleDigest from generated source ID, display name and dimensions. That value is not a real HWND/monitor-origin binding. An OS picker result's name/size must not be guessed into global desktop coordinates. Microsoft lists GraphicsCaptureItem properties as DisplayName and Size; CreateForWindow consumes a known HWND, rather than retrieving one from a picked item. Verify a genuine supported source-origin binding before producing desktop arrows. Never fall back to foreground-window identity or titles when ambiguous.
10. Onboarding CompleteStep currently advances status by button click. It does not run the genuine selected-source/Ask/overlay/Stop chain. Connect progress to actual verified lifecycle outcomes and retain first meaningful success/usability measurement; do not call the existing synthetic step counter an installed novice journey.

## Next implementation sequence after the campaign is terminal

- Close source identity/geometry and transport interface decisions against ADR002/010, with exact source-backed feasibility and refusal behavior. Do not relax OS selection, grant, model-accounting or geometry requirements to make a demo pass.
- Implement actual per-launch bootstrap and mutual typed bidirectional pipe flow using the existing native owner and Python service boundaries. Keep launch secrets out of command arguments, environment dumps, disk and logs; use a bounded inherited local channel. Test actual process-to-process traffic, wrong identity/key/version, altered deadline, duplicate/oversized frames, hung peers, disconnect and Stop.
- Bind the real selected-source receipt and current host consent to exact capture authorization; transfer one-shot image data through bounded memory. Prove zero pixels before authorization and wipe/revoke after Stop or source loss.
- Wire actual Ask, host dispatch, validated source-bound answer and visible presentation. Preserve current grant/cancel/source checks before every release and keep default unavailable-provider behavior truthful. A provider-free document answer must disclose its source and limits and cannot replace promised screen-understanding qualification.
- Implement actual inert visible highlights from qualified source/target geometry, invalidate on movement/resize/source/Stop, and provide text alternatives. Connect onboarding and return-to-Fleet affordances to real outcomes.
- Run a compiled/native owned-window journey with an actual Python host process and controlled provider route for plumbing; separately run approved real-provider/content, installed novice/accessibility and buyer-release campaigns. Keep all missing tiers open.
